# Implementation Notes: Fretboard Foundation

**Feature:** fretboard-foundation
**Created:** 2026-11-15

**Purpose.** The running record of decisions, edge cases, deviations and lessons for this spec. Implementers update it as they work: add a numbered entry under Technical Decisions when a choice is made, add edge cases when found, and write a Deviation entry (with the reason) whenever the code departs from `spec.md`, `architecture.md`, `data-dictionary.md` or `tasks.md`. Update the affected spec file in the same change so the files agree. Decisions D-01 to D-33 were made by the spec builder while the user was away (non-interactive run); where one rests on a judgement call it names the open question that lets J overrule it.

## Technical Decisions

| ID | Decision | Why | Revisit when |
|----|----------|-----|--------------|
| D-01 | **Selection, instrument and handedness live in Rust** (`src-tauri` `Explorer` behind a mutex); the UI sends actions and receives an `ExplorerSnapshot`. | G-3.2 (every feature sets the selection through the same core command), AGENTS.md ("anything a test should check is computed in Rust"), and it makes cycling, announcements and notices testable in Rust. | P2/P3 add run and song mode: they reuse `apply`, so the explorer state may become one of several selections (multi-window, UX-4.1). |
| D-02 | Public API string numbers are `1..=6` with 1 = high E (glossary); internal arrays are low to high (index 0 = string 6), `StringNumber::index() = 6 - n`. | Matches the PRD vocabulary and the architecture's "low to high" `Tuning`. A single conversion point avoids off-by-one bugs. | never |
| D-03 | Frets are **absolute from the nut**; an unfretted string is `StringState::Open` and sounds at the capo fret; frets below the capo are unavailable and never highlighted. | Glossary ("fret numbers shown are absolute") and E-FB-4/LH-3. `Open` instead of `Fretted(capo)` keeps the "open string" ring and the open-string bonus meaningful. | never |
| D-04 | **The selected chord is the sounding chord.** Voicings are searched for the sounding chord with the capo applied; the label shows the shape name and the sounding name (`CapoLabel`), emphasis set by `CapoNames`. For the curated library, shape chord = sounding chord minus capo minus the tuning's uniform shift (Half-step down, Whole-step down). AC-LH-5.1 ("Capo 2, chord shape G → G shape (sounds A)") is tested as: sounding chord A, capo 2, open G shape → "G shape (sounds A)". | Keys and songs stay absolute; the PRD's default is shape names with sounding in brackets (LH-5). | J answers Q-7 differently. |
| D-05 | **`ts-rs` for types plus a generated `commands.ts`** built from an in-repo `CommandSpec` manifest; a unit test keeps the manifest, the x-macro command list and the capability permissions in step. | ts-rs generates types only; tauri-specta 2 is pre-release (PRD FR-003); AGENTS.md demands generated command wrappers. | tauri-specta 2 is stable: replace the generator, keep the types. |
| D-06 | **MPM** (McLeod) pitch detection, own implementation, direct NSDF, 2048-sample window, 512 hop, clarity threshold 0.80, k = 0.93. | Built-in clarity maps to confidence; no new dependency; see research.md Q1. | Profiling shows more than 2 ms per window (then FFT) or recorded guitars fail ±3 cents. |
| D-07 | Karplus-Strong synth, 16 preallocated voices, fractional delay, mono, `f32`, soft limiter. | Cheap, licence-free, tuned (also used for reference tones). SoundFont is P1b. | P1b sound-asset work. |
| D-08 | `mackey-audio` depends on `mackey-theory` only; the **app** converts instrument → `TunerTarget`s and `PlaybackPlan` → `SynthCommand`s. | The AGENTS.md table does not allow audio → voicing, and `mackey-rhythm` arrives in P1b. | P1b adds the rhythm dependency. |
| D-09 | Settings: one `settings.json` with a `version` field, `#[serde(default)]` groups, unknown fields ignored, atomic write (temp + rename), corrupt file renamed `.bak-<ts>` and defaults used with a one-time notice, values clamped on load. | NF-23 (never lose input), NF-15 spirit, forward compatibility. | `mackey-store` takes over settings in P2 (PRD open question: resolved yes). |
| D-10 | Curated shapes are `const` tables in Rust (not data files). | Pure crate, no I/O, compile-time checked, trivial to test; the library is small (about 30 shapes plus 5 movable CAGED templates). | The library grows past a few hundred entries. |
| D-11 | Search scoring weights live in one `const` table (span −3/fret, fingers −2, open string within frets 0..=4 +2, root in bass +4, skipped inner string −6, mutes beyond two −2, lowest fret above 7 −1/fret); result cap 24; ordering inside groups by score then lowest fret. AC-FB-5.1/5.2 calibrate it. | Testable, adjustable, documented. | A teacher or J disagrees with the first-listed voicing. |
| D-12 | Triad view for a seventh chord uses the root triad and shows "Triad of Cmaj7: C E G" (FB-6.3); `Inversion::Third` exists but only for the all-tones/voicing code paths, and the triad view clamps to three inversions. | FB-6.1 allows root/1st/2nd only. | A later phase adds four-note drop-2 voicings. |
| D-13 | Tuner time is counted in samples (`ms = samples * 1000 / sr`), never from a wall clock. | Deterministic tests; no clock in a pure module. | never |
| D-14 | UI mocks replay **recorded scenarios generated from the real Rust core** (`ui/src/mocks/scenarios.json`), not hand-written snapshots or TS theory. | Keeps ADR 0007 intact ("never re-implement theory in TypeScript") and the mock honest; stale mock data is caught by `make bindings-check`. | Scenarios grow beyond a maintainable size. |
| D-15 | `make build/test/lint/cover` create `ui/dist/index.html` (stub) if missing. | `tauri::generate_context!` fails without `frontendDist`; avoids building the UI for Rust-only jobs. | The Tauri crate is split or excluded from the default workspace members. |
| D-16 | Coverage exclusions by regex: `src-tauri/src/main.rs`, `src-tauri/build.rs`, `src-tauri/src/bindings.rs`, `crates/mackey-audio/src/io/`, each with a comment (device and runtime glue). Everything else counts. | PRD risk row ("exclude only thin device and Tauri-runtime glue"). | Glue grows logic: move logic into pure code instead of widening the list. |
| D-17 | `catch_unwind(AssertUnwindSafe(..))` guard around every command body; `Mutex::lock` poisoning recovers with `into_inner` and logs. Release profile keeps `panic = "unwind"` (the default). | NF-24. `panic = "abort"` would defeat the guard. | never |
| D-18 | `roman_to_chord` returns `Result<Chord, RomanParseError>` (docs/architecture.md shows `Option<Chord>`); update the architecture doc in task E8. | The UI needs to say why a numeral failed (NF-22). | never |
| D-19 | `Key` stores `tonic: Note` and `mode: Mode`; the F#/Gb and D#/Eb choice is the tonic's spelling; offered tonics are validated at construction; `Key::new_normalised` applies G-1.4 and returns a notice. | Spelling is determined by the key; invalid keys unrepresentable. | never |
| D-20 | `playback_plan` is a pure function in `mackey-voicing` returning `PlannedNote`s with millisecond offsets; the app converts to samples at the output rate. | Testable without audio; keeps `mackey-audio` independent of voicing (D-08). | P1b transport timing needs sample-exact scheduling (then convert in `mackey-rhythm`). |
| D-21 | **Scale pattern algorithm.** Pentatonic box *k* starts at scale degree *k* on string 6 at the lowest fret at or above the capo whose note is that degree (box 1 = the root; open position allowed, so E minor box 1 uses open strings). Notes are then assigned in ascending scale order, two per string (pentatonic) or three per string (7-note), frets derived by pitch arithmetic per string so every tuning works. Boxes are ordered by lowest fret; `P` cycles in that order. 3-notes-per-string patterns use the same rule with degree *k* = 1..=7. AC-SC-3.1 verifies it (A minor: s6 5,8; s5 5,7; s4 5,7; s3 5,7; s2 5,8; s1 5,8). | Generic over tunings (LH-4) with no hand tables; matches the standard boxes. | J prefers fret 12 for E boxes (Q-8). |
| D-22 | Voicing list order: groups Open, Barre and CAGED, Other; inside a group by score. Voicing cycling wraps within the group, then continues into the next group, then wraps to the first (FB-9 table). | FB-5.2, FB-9. | never |
| D-23 | Triad placements are enumerated in fret order; the default is the lowest; `P` moves to the next placement and the counter reads "k of n". An inversion with no playable placement stays selectable and shows `TriadResult::Unavailable` with the notice "Not playable on these strings within 4 frets" (FB-6.4) instead of being skipped. | AC-FB-6.1 expects the lowest placement (C: E s4 f2, G s3 f0, C s2 f1). Showing "unavailable" matches the PRD wording. | User testing finds skipping better. |
| D-24 | Arpeggio positions: start fret *s* with the window `s-1..=s+4` (four-fret window plus one fret each side, AC-FB-7.1: position 5 → frets 4..=9); valid positions are those whose window contains every required chord tone at least once; default per FB-7.4. | AC-FB-7.1 | never |
| D-25 | The explorer area, tuner and settings are separate **areas** in `UiState`; selection state is in Rust but the **active area** is UI view state. | ADR 0007 (UI holds view state). | Home arrives (P4). |
| D-26 | `R` (relative major/minor) toggles only Major ↔ Natural minor; for other modes it is disabled and the live region says "No relative key for E Dorian". | FB-2.4 says "relative major/minor toggle"; the PRD defines nothing for modes. | J wants Dorian ↔ parent major. |
| D-27 | Input devices are identified by the cpal device name string; the saved `input_device` that is no longer present falls back to the default silently with the E-TU-5 notice. | cpal gives no stable ids; acceptable for personal use. | Duplicate device names appear. |
| D-28 | Single-key shortcuts ignore events whose target is `input`, `textarea`, `select`, `[contenteditable]`, and `Space` ignores a focused `button`/`a`/`[role=button]` (so Space activates the button). | UX-6 and normal accessibility; otherwise Space would both press a focused button and trigger Play. | never |
| D-29 | `ExplorerSnapshot` includes `selection` so the UI controls are driven from Rust values, and the UI never infers "which voicing is selected" itself. | G-3.2, ADR 0007. | never |
| D-30 | The Tauri `Info.plist` and `bundle.iOS.infoPlist` carry `NSMicrophoneUsageDescription`; the microphone is requested only when `tuner_start` first opens the input stream. | NF-7.2. | The Swift plugin takes over permission handling. |
| D-31 | Every `ExplorerSnapshot` has a `revision` (u32, incremented on every state change); the UI serialises commands through one promise queue and drops any snapshot older than the one it holds. | Two quick key presses can resolve out of order across IPC; without it the neck could show a stale selection (found in the Step 2 review). | never |
| D-32 | Selecting a chord from focus None (or via the chord field) sets the view type to All tones (so AC-FB-4.1 shows D, F#, A, C); selecting a chord while a chord is focused keeps the current view type. | AC-FB-4.1 says "All tones shows ..." after typing `D7` with no prior view choice; keeping the view on chord-to-chord moves is what cycling expects (F-2). | J finds the reset surprising. |
| D-33 | Extended symbols outside FB-4.3 (`Cmaj13#11`, `C7b9`) are errors this run (Q-9); the error carries no suggestion. | FR-010 copies the FB-4.3 grammar; E-FB-2 and E-FB-1 conflict on `maj13#11`. | J answers Q-9. |
| D-34 | **Checked newtypes (`PitchClass`, `Accidental`, `Degree`, `ReferencePitch`) have hand-written `Serialize`/`Deserialize`** (a `checked_serde!` macro) that validate on the way in; `Interval`, `Pitch` and `Key` keep private fields, derive `Serialize` and deserialize through a private repr plus their validating constructor. | `ts-rs` 12 warns that it ignores `#[serde(try_from, into)]`; the macro keeps one validating path and a clean build. A bad number in settings or an IPC message is an error, never an invalid value. | ts-rs learns `try_from`. |
| D-35 | `Interval::apply`, `apply_down`, `between` and `invert` return `Result<_, TheoryError>`; `Chord::tones` and `Scale::degrees` fall back to a sharp spelling of a tone that would need a triple accidental (only from a double-accidental root such as `C##`). | The data dictionary signatures returned plain values; a triple accidental cannot be represented. Returning `Result` keeps the no-panic rule without lying. | never |
| D-36 | `Accidental::symbol()` shows a double sharp as `##` (the dictionary said `x`); `Note::from_str` also accepts `x`, `♯`, `♭`, `𝄪`, `𝄫`. `Note::simplified()` takes no preference: a double sharp that lands on a black key becomes a sharp (`E##` to `F#`), a double flat a flat (`Fbb` to `Eb`), natural results are natural (`F##` to `G`). | One text form round-trips through `FromStr`; the direction of the alteration is the better tie-break than a global preference (G-1.6). | never |
| D-37 | **Parser suggestions.** An unknown quality gets a suggestion only if the root is valid, the token has no `#`/`b` alteration, and a known spelling is within edit distance `min(2, len/2)`; ranking is distance, then shared prefix, then the longer spelling (`Amj7` to `Amaj7`, not `Am7`). Text after the longest valid quality prefix is `TrailingInput` if it starts with something that cannot be part of a quality (space, `!`, emoji), otherwise `UnknownQuality` for the whole token. `ChordParseError` variants also carry `symbol` (the whole trimmed input) so the E-FB-1 message can be built from the error alone; spans use a `Span { start, end }` type. | Q-9 default: `C7b9` and `Cmaj13#11` get the error without a suggestion; the length cap stops `alt` suggesting `aug`; a wrong root makes a quality suggestion misleading. | J answers Q-9. |
| D-38 | **Function analysis rules.** In key means every tone (and the slash bass) is a scale tone. Not in key: a dominant-family chord (major triad, 7, 9, 11, 13) on the fifth above a diatonic major or minor degree other than I is a secondary dominant (`V/V`; the badge uses plain `V`); a chord that is diatonic (triad or seventh) to the parallel mode is borrowed (major keys: natural minor; minor keys: harmonic minor, then major; other modes: major and natural minor). Dominant-family chords try secondary dominant first, other chords try borrowed first. Borrowed numerals are written against the home key scale (`bVII`), except harmonic-minor chords, which are numbered against harmonic minor (`V`, `vii°`) so E7 in A minor reads "V7, borrowed from A harmonic minor". `ChordAnalysis` also carries the `key` so `badge()` can name the source scale; `Mode::NaturalMinor` displays as "minor" ("G minor", PRD wording). | AC-FB-4.1 and the PRD badge example; a natural-minor key would otherwise label its own V as "Not in key". | The teacher review of badges (P1). |
| D-39 | `Chord::pitch_classes()` includes the slash bass; `ChordQuality::roles()` returns a `Vec<ToneRole>` (not `&'static`); `Key::all_offered(mode)` lists the 12 keys of a mode in circle order; `Key::next_fifth`/`prev_fifth` do not remember the F#/Gb choice across the far side of the circle (twelve steps come back to the same pitch class, in its other spelling when the start had six accidentals). | The voicing search needs the bass in the set; a static slice cannot be derived from the intervals; the picker needs the list; remembering the choice would need extra state in `Key`. | The UI wants the spelling remembered. |
| D-40 | **The AC-P0-1 table (`tests/chord_spelling.rs`) and the no-context key table (`tests/spelling.rs`) were calculated by a separate letter-and-semitone script, not by this crate, then spot-checked by hand (D7, Bbmaj7, G#dim7, Db m7b5 = Db Fb Abb Cb, F# aug = F# A# C##)** and committed as literals. | 252 + 26x12 rows by hand is error-prone; an independent calculation plus review keeps the "not generated from the code under test" rule. | never |

| D-50 | Fingering rank rule (`assign_fingering`): barre detection first (the lowest pressed fret held by two or more distinct pitches with no open string between them is one barre by finger 1), then remaining pressed notes get fingers 2 to 4 in order of ascending fret, then string. More than four distinct fingers rejects the shape. Identical open strings (E-FB-6) count once. Teaching choice: the small F (`xx3211`) is a barre of kind Barre (strings 2 to 1 at fret 1). |
| D-51 | Group rule: Open = every pressed fret at most 4 and an open string sounds (or curated open shape); Barre = a barre is drawn; Position = otherwise. `lowest_fret` is the lowest pressed fret, or the capo fret when nothing is pressed. List groups are capped `[ceil(max/3), ceil(max/2), max]` so CAGED forms are never cut by open-position variants. |
| D-52 | Root-bass is a hard rule: the lowest sounding pitch is the chord's bass (root, or the slash bass). Essential tones: root plus third (or the sus tone); the fifth may be omitted only with `allow_omitted_fifth`. Power chords need 2 sounding strings, everything else 4. |
| D-53 | Score weights (`rules::weights`): span -3, finger -2, open string +2, root bass +4, skipped string -12, extra mute -2, high position -1, sounding string +3, complete chord +2, curated +50. First calibration; 32 (chord, tuning, capo) first-voicing rows are pinned by `fb_5_1_first_voicing_table_over_tunings_and_capos`. |
| D-54 | Curated shapes (open tables, CAGED templates, Drop D) are re-verified against the real tuning and capo before they are offered, so a half-step-down or capo never shows a wrong note. The movable C7 C-shape needs five fingers, so it is not a template (documented in `shapes/caged.rs`). |
| D-55 | Triad placements are ordered by the lowest sounding fret counting an open string as the capo fret; seventh chords use their root triad (D-12); a third inversion of a triad is "unavailable" with a reason. `triad_ladder` gives root, 1st, 2nd for AC-FB-6.2. |
| D-56 | `scale_patterns` excludes the full neck (`full_neck` is separate); harmonic minor and blues have no patterns. A pattern that runs off the neck (high capo, 19 frets) is not offered; found by the property test (regression file committed). Patterns are ordered by lowest fret. |
| D-57 | The overlay in follow mode: a minor or minor-7 chord gets the minor pentatonic of its root (SC-1), everything else the SC-4 choice (`scale_for_chord`: diatonic -> key scale; dominant -> Mixolydian; major -> Ionian; minor -> Dorian; diminished -> Locrian; sus, power and augmented fall back to the key scale). |
| D-58 | `Selection.position` has a dual meaning: the triad placement index in Triad view, the arpeggio start fret in Arpeggio view. The first VoicingNext from another view switches to Voicing view and shows index 0; P in Voicing view moves to the next voicing with a higher lowest fret. |
| D-59 | G-3.3 key change: a diatonic chord moves to the same degree (sevenths stay sevenths); a chord outside the key is kept with the notice "Chord is not in the new key; kept as it was". |
| D-60 | Wire format: `StringState` is internally tagged (`kind`, snake_case); `VoicingResult` is adjacently tagged; checked newtypes (`StringNumber`, `Fret`, `Capo`, `FretCount`, `Bpm`) serialise as numbers and validate on deserialise; ts-rs exports them as `number`. |
| D-61 | Out-of-scale degree labels are spelled from the note: F# in C is `#4`, Bb is `b7` (the PRD examples G-2.2 say "1, b3, 5"); labels never carry double accidentals (G-1.6), the theory spelling goes to the tooltip. |
| D-62 | Playback (B11): eighth = `30000 / bpm` truncated (428 ms at 70 bpm, as the spec says), the n-th start is `n * 30000 / bpm` truncated once (so 428, 857, 1285...). Strum: 30 ms apart, each string rings 1500 ms. All Tones view plays the selected voicing; Triad plays the selected placement; a clicked note is a quarter note. Scale plays the overlay scale if one is chosen, else the key scale, one octave plus the tonic from the lowest tonic in the visible range. |
| D-63 | Library code indexes `[T; 6]` arrays directly only where the index comes from a `0..6` loop or a `StringNumber`; everything else uses `get`. `unsafe`, `unwrap`, `expect` and `panic` are absent from `src/`; the two `#[expect]` allowances carry reasons (a flat FB-9 action dispatch, a fret-cell helper in the shape tables). |
| D-64 | **AC-FB-9.1b is asserted as a percentile.** The Playwright spec measures 100 `keydown` to DOM-mutation times (5 warm-ups discarded). Median is about 7 ms; the 90th percentile must be <= 16 ms and no redraw may exceed 100 ms, because a shared runner has the odd GC pause that a strict "each <= 16 ms" turns into a flaky test. |
| D-65 | The UI command layer stays in `ui/src/ipc/` (D-45) rather than the `ui/src/commands/` of the plan, and the promise queue is `ipc/queue.ts`. Components get one `UiStore` through a React context. |
| D-66 | State management is a small hand-written `UiStore` over `useSyncExternalStore`, not Zustand: one store, no dependency. Snapshots older than the held `revision` are dropped (SAC-18). |
| D-67 | `ExplorerSnapshot` also carries `notices` (core notices such as a capo moving a position) and `announcement` (the live-region text), so the UI invents no wording. `fit_selection` takes no margin argument. |
| D-68 | Two commands were added to the architecture table: `tuner_targets` (the string targets for the tuning and capo, available without a microphone so reference tones work when the mic is denied, E-TU-2) and `take_settings_notice` (the one-off "settings file was damaged, a backup was kept" notice). |
| D-69 | **The mock is a recorded state graph.** `bindings.rs` drives the real `AppState` through scripted scenarios and records nodes (hash of selection, instrument panel, chord status, chord text and settings) and edges keyed `command|canonical-args`. The mock replays edges; an unrecorded path rejects with an `Internal` error, so tests stay inside recorded paths. It is about 2.6 MB, loaded with `?raw` plus `JSON.parse` to keep TypeScript from inferring a type for it. The mock `voicingsFor` is a stub (the voicing list comes with the snapshot). |
| D-70 | **No per-command ACL manifest yet.** `capabilities/default.json` keeps `core:default`; app commands registered with `generate_handler` are callable without extra permissions in Tauri 2. The `allow-<name>` set from D1's acceptance text is left for a hardening pass. |
| D-71 | Inversion and string-set controls for triads are steppers (previous/next with the current value as text) rather than the segmented pickers of the sketch; they work the same by keyboard and touch and fit narrow widths. |
| D-72 | Shapes: root = rounded square, third, fifth, seventh and extension = filled circles, scale tone = ring, single note = diamond. A Vitest test parses `tokens.css` and checks 4.5:1 for marker text and 3:1 for the outline and the scale ring in both themes. |

| D-80 | **`mackey-audio` timing budget (AC-NF-9, AC-TU-1.1).** The first reading is made as soon as one 2048-sample window exists (42.7 ms at 48 kHz, 46.4 ms at 44.1 kHz), then one per 512-sample hop (about 94 per second). A note that starts inside that first window is recognised once about three periods of it are in the window (NSDF clarity needs the overlap: clarity is about (L-P)/(L-P/2) for L samples of tone of period P, so L >= 3P reaches 0.8). Measured with a decaying guitar-like tone and 20 ms of silence first: first pitch reading 22.7 to 38 ms after onset for E4, A2 and E2 at 44.1 and 48 kHz (budget 150 ms); "In tune" 340 to 353 ms after onset (budget 400 ms; the 300 ms hold starts at the first in-tune reading). Tests assert both the reading's sample-counter time and the delivery time of the block that carried it (device buffers of 256, 512 and 1,024 frames). | The 2048-sample window cannot be shortened without losing 60 Hz detection, but the budget holds with margin, so no change to the window is needed. | A window shorter than 2048 or a rate below 44.1 kHz |
| D-81 | **`TunerReading` semantics fixed in code.** `cents` is always the offset from the nearest chromatic note (-50 to +50, median of the last three for that note); in string mode `target.cents` is the offset from the target string (may exceed 50) and drives `direction`, `in_tune` and ticks. `direction` is `InTune` as soon as the smoothed offset is within 3 cents; `in_tune` is the held version (300 ms). For 500 ms after the pitch is lost the last reading is shown again (status `Pitch`), then `NoStablePitch`, or `LowConfidence` when a candidate with clarity 0.5 to 0.8 exists, and `TooQuiet` once the level has been under -50 dBFS RMS for 3 s. `TooLoud` (2 consecutive samples at or above 0.99) holds for 1 s after the last clip so it does not flicker. | Matches TU-1 to TU-2.2 and E-TU-3/4/6; the hold avoids a flashing needle between plucks. | UX review of the tuner screen (D phase) |
| D-82 | **Two-string detection needs no special case.** For 110 Hz plus 165 Hz the NSDF peaks are low at both periods, so the tuner shows `NoStablePitch` (the TU-1.4 message required by E-TU-6) or the strongest pitch when one string dominates; the test asserts that a pitch, when shown, is one of the two strings and that `in_tune` is never true without a pitch. | E-TU-6 says "strongest pitch; if confidence is low, TU-1.4 message". | Real-guitar testing by J |
| D-83 | `CentsOffset` newtype from the data dictionary is not introduced; `cents_between`, `cents_from` and `nearest_pitch` return plain `f64`/`(Pitch, f64)` with the range documented. `nearest_pitch` returns `Option` (None outside MIDI 0 to 127 or for a non-positive frequency). | A newtype adds ceremony with no invariant to protect (the value is a signed distance, not a validated range). | The UI needs a bounded type |
| D-84 | **Detector hardening.** `analyse` returns `None` for non-finite samples, absurdly large samples (energy overflow) and silence below -100 dBFS RMS, and normalises the window to a peak of 1 so f32 products cannot overflow. The peak scan treats NaN as "not positive". Regression test `huge_samples_neither_hang_nor_overflow` (a window of 3e38 values made the scan loop forever before the fix). `DetectorConfig::new` uses a 4096-sample window above 51.2 kHz so the window still holds 2 periods of 60 Hz; rates outside 22,050 to 192,000 Hz (or those that leave under 1.5 periods of 60 Hz in the window) are `AudioError::InvalidConfig`. | A panic or hang in the analysis thread must be impossible (E: analysis thread). | Never |
| D-85 | **Synth details.** Loop = line length + 0.5 sample (two-point average) + first-order allpass whose delay is corrected for its own frequency-dependent phase delay (three fixed-point steps in `start`), which brings pitch within 3 cents for 82 to 880 Hz (checked through the detector). Decay is T60 3 s per loop gain; because the loop lowpass removes high partials first, the waveform peak falls faster than the fundamental (about -33 dB after 1.2 s for A2). Voices whose envelope is under -100 dBFS are freed. `NoteOff` raises the loop damping (gain 0.85) rather than cutting, so there is no click. Volume changes ramp (10 ms). Frequencies are clamped to 30 Hz to a quarter of the sample rate; non-finite frequency or velocity is ignored. The random excitation is a seeded xorshift owned by the synth: output is a pure function of the command stream. | Cheap, deterministic, allocation-free (delay lines sized for 30 Hz in `new`). | P1b sound-asset work |
| D-86 | **Coverage exclusions for `mackey-audio`** narrowed from D-16's `io/` to `io/devices.rs`, `io/input.rs`, `io/output.rs` (the cpal calls and the stream-owning threads; `COVER_IGNORE` in the `Makefile`, AGENTS.md note updated). The decisions inside the glue were moved into `io/select.rs` (device and format choice, cpal error mapping) and `io/pump.rs` (`OutputCore` callback body, mono mix-down, zero-input permission watch, ring-to-tuner pump), which stay measured and are tested with fakes (`rtrb` rings, synthetic samples). | The task asked for the exclusion only where truly untestable. | A CI runner with a loopback audio device |
| D-87 | **Glue structure.** cpal 0.18 (its API differs from 0.15: `DeviceId`, `ErrorKind`, `description()`) is used. A stream is built and owned by a dedicated thread (`mackey-output`; the tuner's `mackey-tuner` thread is also its analysis thread) because cpal streams are not `Send` on every host; handles are `Send + Sync`. `OutputHandle::send` never blocks (queue of 512; full means the command is dropped and counted, `Err(DeviceUnavailable)`), and `TunerInput` holds at most one `InputHandle` (start replaces, stop without start is a no-op, E-TU-5 fallback to the default device with `DeviceDisconnectedUsingDefault`, saved device missing at start gives `DeviceChanged`, `PermissionDenied` from the OS or after a second of exact zeros). Device ids are cpal's `DeviceId` strings (host and device), not bare names (data dictionary said name). Input is mixed down by averaging channels (not a selectable channel). Supported sample formats: f32, i16, i32, u16 at 48 kHz then 44.1 kHz (else the device default). No `OutputBackend` trait: the testable part is `OutputCore` plus `choose_config`, which needs no fake device. | Simplest design that keeps `unsafe` out and the callbacks real-time safe. | An iPad audio-session task (platform code lives in the plugin) |
| D-88 | `assert_no_alloc` (BSD-1-Clause, added to the `deny.toml` allow list as a permissive licence) is a dev-dependency used by `tests/synth_noalloc.rs`; its allocator is active in debug builds only, so the release run of `make props` executes the same calls without the guard. The harness was checked by hand (an allocation inside the guard aborts the process). `#![forbid(unsafe_code)]` stays: the test only names the crate's safe `AllocDisabler` static. | NF-8.1 needs a proof, not an assumption. | Never |
