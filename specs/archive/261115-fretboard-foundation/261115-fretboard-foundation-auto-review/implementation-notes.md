# Implementation Notes: Fretboard Foundation Auto Review Fixes

**Created:** 2026-11-15

Update after each fix with the decision, edge cases and a brief self-review (code and design review per fix).

## Technical Decisions

### FR-001 pattern stepper (P0)

- Root cause confirmed: `scale_patterns` sorted by lowest fret, and the view labelled by index. Fix: sort by pattern number (box order) and build the label from `PatternKind` in one place (`patterns::pattern_label`), used by the view's list position and the announcement ("Box 1 of 5", "Pattern 3 of 7"). No persisted `pattern_index` exists in settings, so no migration.
- Regression tests: `crates/mackey-voicing/tests/pattern_stepper.rs` (four tests, failed first: box 4 shown as "1 of 5"); the hand-table test now asserts box order; the `a_minor_pentatonic_box1` snapshot was wrong before (it drew frets 0 to 3) and now draws frets 5 to 8 (reviewed by hand against AC-SC-3.1).
- Mock scenarios regenerated by `make bindings`; the UI renders the label it is given, so no TypeScript change.
- Screenshot `real-explore-a-minor-pentatonic.png` regenerated and read: frets 5 to 8, "Box 1 of 5". Caption in `user-docs/explorer.md` fixed.
- Self-review: logic stays in Rust, label format in one function, no new public API, clippy pedantic clean (Scale passed by value).

### FR-003 triad inversion label (P0)

- Fix in `triads.rs`: a combination is kept only when pitch(low string) < pitch(middle) < pitch(top), computed from the tuning's open MIDI notes plus fret. Because the three tones are distinct pitch classes, ascending order puts the inversion's bass tone lowest. Placements that were really another inversion (open string at fret 12 or above, or a high fret under an open string) are now dropped, and `Unavailable` is returned when none remain.
- Regression tests (failed first): proptest `fr003_every_triad_placement_ascends_and_has_the_labelled_bass` over 12 roots, all qualities, preset and custom tunings, capo 0 to 12, all string sets and inversions; and `fr003_c_standard_s345_root_has_no_open_g_undercut`. The older property `fb_6...` only checked the lowest string, which is why it passed.
- Existing snapshots and doc tests unchanged.
- Self-review: one added filter in the existing triple loop, no new API; search cost unchanged (the filter is cheaper than building a voicing). Criterion bench not re-run locally (disk); the loop only gets shorter.

### FR-002 tuner pacing (P0)

- `src-tauri/src/tuner.rs`: `Throttle::accept(reading, wall_ms)` requires 30 ms on the stream clock and the wall clock (injected, so tests use a fake clock); notices and status changes still pass at once. `AppState::tuner_start` supplies `Instant`-based milliseconds.
- `mackey-audio/src/io/pump.rs`: `pump_input` takes a sample bound; new `Analyzer::step` (bounded to about 100 ms of audio, returns the wait: 2 ms idle, 1 ms yield after a full step, 100 ms once unpaced) and `PaceGuard` (over a 1 s wall window, more than 2.5x the nominal rate means unpaced; a stalled second of backlog stays below it). `input.rs` just calls `step` and sleeps for `step.wait`. New `TunerNotice::InputNotPaced`, shown by `TunerScreen` instead of "Too quiet"; bindings regenerated.
- Decision (PRD Q3): notice only, no automatic fallback to another device. Exact-zero streams keep the existing `ZeroWatch` path (permission denied message).
- Tests: `fr002_a_fast_source_is_limited_in_wall_clock_time` (50x source, at most 35 emits per wall second), `fr002_a_step_is_bounded_and_yields_however_fast_the_producer_is`, `fr002_unpaced_input_is_detected_announced_once_and_stops_analysing`, `fr002_a_paced_input_and_a_one_second_burst_are_not_flagged`. The old state test that expected 290 to 330 emits for a burst delivered in zero wall time was changed to expect the wall-clock limit. The new `pump.rs` tests were written together with the new API (no earlier API to fail against); each was checked to exercise a real branch.
- Not done: the manual ALSA null-device CPU check (no audio hardware path in this container); covered by the fake clock tests. D-91 marked resolved in the archived notes.
- Self-review: no allocation or lock added to cpal callbacks (only the worker changed); no new dependency; policy is pure and device-free. FR-005 is partly met here (see its task).

### FR-004, FR-006, FR-007 (P2)

- FR-004: spec.md traceability named files that do not exist (`scale_patterns.rs`, `view_key_notes.rs`, `voicings_standard.rs`, `no_voicing.rs`, `capo.rs`, and five `ui/e2e` files). A one-off script that resolves every test path in `spec.md` and `docs/prd/09-traceability.md` against `git ls-files` found them; all were corrected to the real files (`patterns.rs`, `pattern_stepper.rs`, `view.rs`, `voicings.rs`, `ui/e2e/explore.spec.ts`). The path check stays a documented review (not added to xtask: it would need a parser for free-form table cells); AC-SC-3.1 is now covered by core (`patterns.rs`), selection, view and announcement tests (`pattern_stepper.rs`). The e2e mock label format agrees because `scenarios.json` is regenerated from Rust.
- FR-006: `'unsafe-inline'` removed from the production `style-src`. React writes the two dynamic styles (needle rotation, level bar width) through the CSSOM (`element.style`), which CSP does not block; only `style=""` attributes in markup and `<style>` elements are. Verified in the real app under Xvfb: Explore (screenshot byte-identical) and Tuner render correctly. The dev CSP keeps `'unsafe-inline'` for Vite's HMR; scripts stay `'self'` only in production. No ADR needed (hardening only).
- FR-007: D-91 marked resolved; Explore caption and screenshot (FR-001); tuner screenshot regenerated (now "Listening…" because the null input is no longer flooding), README, images README and user-docs updated; traceability table names the new tests; troubleshooting documents the new notice.
- FR-005 (partial, deferred remainder): the loop's decision logic (bounded step, yield policy, unpaced and silent-stream detection) moved to `pump.rs` and is unit tested with a fake ring and clock. Command handling and stream-loss fallback stay in `input.rs` because they need a live `cpal` session; `input.rs` therefore stays in `COVER_IGNORE`, now holding only thin cpal glue. Removing it from the exclusion needs a coverage run, which is CI-only here.
